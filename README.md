# 豆瓣 Top250 电影爬虫、分析与推荐

个人练手项目：从爬虫、数据清洗、数据库设计，到 SQL 分析和电影推荐，完整走一遍数据处理流程。
数据为豆瓣电影 Top250 的 250 部电影。

**技术栈**：Python（requests、BeautifulSoup、pymysql）· MySQL 8.0 · Docker Compose · Git

## 亮点

- **数据清洗**：多次上映的电影会有多个年份，导致国家、类型字段错位，改为从后往前解析；
  导演名在页面上可能被截断，先检测并输出警告，再清理。
- **实体判重**：导演中英文名分列存储，按任一名字匹配合并，
  发现并合并了 3 位因写法不同被重复记录的导演（198 → 195）。
- **推荐算法**：类型、导演、国家各自按 1 / 出现次数加权，权重由数据自动计算，
  越稀有的共同点权重越高；年份相近度只用于同档内排序，不打乱主要排序。
- **可复现**：表结构导出为 `schema.sql`，数据库首次启动时自动建表。

## 快速开始

**环境要求**：Docker、docker-compose；宿主机 Python 3 及 pymysql（`pip3 install pymysql`）

```bash
git clone https://github.com/LuTianming-Timmy-1111/douban-project.git
cd douban-project

# 1. 配置数据库密码
cp .env.example .env
vi .env

# 2. 启动数据库（首次启动会自动建库、建表）
docker-compose up -d db

# 3. 运行爬虫，写入原始表 movie
docker-compose up spider

# 4. 拆分为规范化的表
./run_split.sh
```

数据库映射在宿主机 **3307** 端口，可用 Navicat 等客户端连接，运行 `sql/` 下的查询。

## 项目结构

| 文件 | 说明 |
|---|---|
| `spider.py` | 爬虫：抓取片名、评分、年份、国家、类型、导演，写入 `movie` 表 |
| `split_tables.py` | 把 `movie` 拆分为规范化的表，导演按中英文名判重合并 |
| `run_split.sh` | 加载 `.env` 后运行拆表脚本 |
| `schema.sql` | 规范化表的结构（不含 `movie`，其结构由 `spider.py` 定义） |
| `dump_schema.sh` | 从数据库重新导出 `schema.sql` |
| `sql/` | 分析与推荐查询（01～07） |
| `docker-compose.yml` / `Dockerfile` | 用 Docker 运行 MySQL 和爬虫 |

## 数据库设计

| 表 | 说明 |
|---|---|
| `movie` | 爬虫写入的原始宽表 |
| `movie_new` | 电影 |
| `genre` / `country` | 类型、国家 |
| `director` | 导演，中文名 `name_cn`、英文名 `name_en` 分列，各自唯一，至少有一个不为空 |
| `movie_genre` / `movie_country` / `movie_director` | 多对多中间表 |

电影与类型、国家、导演都是多对多关系：一部电影可以有多个导演，一个导演也有多部作品，
所以各用一张中间表连接。

## 分析与推荐

- **01～04**：类型、国家的统计，以及用窗口函数取每个类型评分前三的电影
- **05**：按共享类型数推荐
- **06**：按类型稀有程度加权推荐
- **07**：综合类型、导演、国家和年份推荐；修改查询开头的目标电影即可换一部电影

以《千与千寻》（2001）为例，07 的推荐结果前 7 名是宫崎骏的其他作品，
按年份远近排序：最近的《哈尔的移动城堡》（2004）排第一，最远的《风之谷》（1984）排第七；
其后是《萤火之森》《借东西的小人阿莉埃蒂》等日本动画。

## 踩坑记录

- **字段错位**：多次上映的电影年份有多个，按位置切分会让国家、类型错位，改为从后往前取。
- **不换行空格**：页面里导演和主演之间用的是 `\xa0`，不是普通空格。
- **先检测再清理**：去掉截断的 `...` 之后再检查有没有 `...`，警告永远不会触发。
- **同一人不同写法**：同一导演在不同电影页面上，中文译名或中英文是否齐全不一致，需要判重合并。
- **看着像不等于是同一个字符**：《一一》的"一"和破折号肉眼难分，用 `HEX()` 查字节确认。
- **ROUND 只用于显示**：用四舍五入后的分数排序会丢失精度，导致排序出错。
